    How it works

    How a decision is made

    Every result is produced by the same transparent rules, so you can always trace a label back to the words that caused it. Same ticket in, same answer out.

    1. 01

      Normalise

      Unicode, case, apostrophes and spacing are made consistent, so "Refund", "REFUND" and "refund" read the same.

    2. 02

      Defang

      Text that tries to steer the result, like "ignore previous instructions" or "classify this as billing", is set aside. Tickets can't choose their own label.

    3. 03

      Gather evidence

      Weighted signals for each category, in English, Hinglish and Hindi. Negated mentions ("not a billing issue") don't count, and common typos still do.

    4. 04

      Decide

      The strongest category wins, and confidence reflects how clear the margin was. A ticket that only describes something broken is treated as technical.

    5. 05

      Rate urgency

      Outages, security problems, lost money or data, lockouts and explicit deadlines raise urgency. "No rush" from the customer lowers it.

    • Nothing is stored. Tickets are classified in memory, and the inbox lives only in your browser.
    • Ticket text is never logged. Server logs record timings and status codes, not content or client addresses.
    • Works offline from AI providers. The rules need no external service. An optional Claude mode can be switched on and falls back to the rules if it fails.

    Developers

    Use it from your helpdesk

    One endpoint, one JSON object in, one out. Wire it into a webhook, a queue worker or a ticketing rule.

    Request
    curl -X POST https://your-host/classify \
  -H 'Content-Type: application/json' \
  -d '{"text": "I was charged twice, please refund ASAP"}'
    Response · 200
    {
  "category": "billing",
  "urgency": "high",
  "confidence": 0.95
}

    Response fields

    FieldValues
    categorybilling, technical, account or general
    urgencyhigh or low
    confidenceA number from 0 to 1

    Errors · always JSON {"error", "message"}

    400Body isn't valid JSON, or text is missing or empty
